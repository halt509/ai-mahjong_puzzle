# ADR-0009: PCとスマートフォンで同じゲームへ入力を割り当てる

- 状態: 採用
- 日付: 2026-07-25
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ4の公開前確認
- 関連仕様: `docs/PROJECT_SPEC.md` 17.5

## 背景

ADR-0008では公開前の簡易確認を物理キーボードのあるPCブラウザへ限定した。その後、ユーザーが実端末で確認し、同じゲームをスマートフォンでも遊べるようにする方針を選択した。

ルール、ゲーム状態、画面構成、Web版ハイスコアは端末間で共通である。PC版とスマートフォン版を別アプリへ分岐すると、同じ変更を二重に保守し、動作差が生じるおそれがある。

## 決定

PCとスマートフォンで同じ`web/mahjong-puzzle.pyxapp`を使用する。Pyxel Web Launcherの`gamepad=enabled`属性を有効にし、タッチ端末ではバーチャルゲームパッドを表示する。

アプリ内では画面操作をアクション単位で定義し、各アクションへ既存のキーボード入力とゲームパッド入力を割り当てる。

| ゲームパッド | 操作 |
|---|---|
| 十字キー | 上下左右へ移動 |
| `X` | 反時計回りに回転 |
| `B` | 時計回りに回転・一覧を閉じる |
| `A` | 配置・決定・開始 |
| `Y` | 役一覧を開閉 |
| `BACK` | 川を開閉 |
| `START` | 開始・結果画面から再開 |

論理解像度256×176と現在の横長画面は維持し、スマートフォンは横向き推奨とする。縦画面専用レイアウトと盤面への直接タッチ操作は今回実装しない。

## 理由

- ルール、画面、セーブ形式、配布物を端末ごとに重複させずに済む。
- Pyxel Webが提供するバーチャルゲームパッドを使い、独自のHTML操作層を追加せずに確認できる。
- 既存キーボード操作を維持したまま、入力境界だけを追加できる。
- 横向きに限定すれば、現在の盤面とサイドバーを再設計せず実端末で評価できる。

## 検討した代替案

### PC版とスマートフォン版を別アプリにする

- 利点: 端末ごとに画面と操作を最適化できる。
- 欠点: ルールや画面変更の二重保守が必要になり、配布物とセーブ元も分かれる。
- 不採用理由: 現段階では入力方式以外を分ける必要がない。

### 盤面上へ独自のタッチボタンを描画する

- 利点: ゲームの配色に合う操作UIを自由に設計できる。
- 欠点: 256×176の盤面領域が狭くなり、タッチ座標、複数タッチ、端末差の検証が必要になる。
- 不採用理由: まずPyxel標準のバーチャルゲームパッドで操作性を評価する。

### 縦画面専用レイアウトを作る

- 利点: スマートフォンを持ち替えずに遊べる。
- 欠点: 盤面、サイドバー、通知、一覧画面をほぼ再設計する必要がある。
- 不採用理由: 実端末で横向き版を評価する前に画面構造を分岐させない。

## 影響

- コード: `app.py`へ操作アクションとキーボード・ゲームパッド対応表を追加する。
- テスト: ゲームパッドによる開始、移動、一覧開閉、再開と配布物への収録を確認する。
- UI: 画面内案内と初心者向けガイドへゲームパッド操作を併記する。
- 将来の変更: 横向き版の実端末評価後に、必要な場合だけ縦画面用の表示アダプターを検討する。
- 移行作業: `.pyxapp`を再生成し、Web Launcher URLへ`gamepad=enabled`を付ける。

## 確認事項

- iPhone SafariとAndroid Chromeで、横向き表示、全ボタン、効果音、通知解除を確認する。
- バーチャルゲームパッドが盤面やサイドバーを隠さないことを確認する。
- 端末のブラウザデータを削除しない限り、同じWeb Launcherオリジンでハイスコアが保持されることを確認する。
- オンラインランキング、端末間同期、縦画面専用UIは今回の対象外とする。
