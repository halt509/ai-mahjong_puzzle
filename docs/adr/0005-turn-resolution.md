# ADR-0005: GameSessionでターン全体を多段解決する

- 状態: 採用
- 日付: 2026-07-24
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ3
- 関連仕様: `docs/PROJECT_SPEC.md` の「10. カン」「11. ドラ」「12. 得点」「12.1 フェーズ3のターン解決順」

## 背景

1回の配置で複数行が変更され、複数の新規カンと和了が同時に起こり得ます。新しいカンドラは同じターンの別行和了へ反映し、同時和了行数は全行の得点倍率へ反映する必要があります。行を1つずつ確定すると、処理順によってドラや倍率が変わる問題が生じます。

また、フェーズ2の`GameState`は盤面・配置・川・136枚整合性に責務を限定しており、この公開APIを保ちながらルール状態を統合する必要があります。

## 決定

`GameState`を内包する`GameSession`を追加し、行ごとの`LineState`、`TurnState`、累計得点、ターン履歴を所有させます。`GameState.place_active()`は従来どおり盤面配置だけを行い、通常ゲームでは`GameSession.place_active()`を入口にします。

ターンは次の多段処理で解決します。

1. 配置と変更行抽出
2. 全変更行の新規カン検出と履歴更新
3. 全新規カンについて表示牌上限まで公開
4. 新規カン行を和了判定から除外
5. その他の行で未取得役を含む候補を抽出
6. 和了行数と連続和了数を確定
7. 同ターンの新しいドラを含めて全候補を採点
8. 各行の最高得点候補を登録し、累計得点を更新

結果は不変な`ResolvedTurn`とし、`KanEvent`と`WinEvent`へ詳細を分けます。ドラ上限を超えた新規カンも履歴とイベントへ残し、対応する`revealed_indicator`を`None`とします。

## 理由

- 全新規カンを和了より先に解決するため、同ターンのドラ適用が入力行順に依存しません。
- 和了候補を先に全行抽出するため、同時和了倍率を正しく確定できます。
- 盤面操作とルール統合の責務を分離し、フェーズ2 APIを維持できます。
- 構造化ターン結果により、フェーズ4で演出や得点理由を後付けできます。
- 同じ入力とseedで結果が決定的になります。

## 検討した代替案

### GameStateへ行履歴と得点を直接追加する

- 利点: 状態オブジェクトが1つで済みます。
- 欠点: 盤面操作だけをテスト・再利用する境界が失われ、フェーズ2 APIの責務が大きく変わります。
- 不採用理由: 既存の盤面操作層を維持する方が責務と回帰テストを保ちやすいためです。

### 変更行を行番号順に完全解決する

- 利点: 1回のループで処理できます。
- 欠点: 後の行で発生したカンドラを前の行へ適用できず、同時和了行数も事前に確定できません。
- 不採用理由: 仕様上、ターン全体のカンと和了を相互に反映する必要があるためです。

## 影響

- コード: `integration.py`がフェーズ3のオーケストレーションを担います。
- テスト: カン行保留、同ターンドラ、再カン、再和了、複数行和了、コンボ、ドラ上限を固定状態で検証します。
- UI: `app.py`は配置時に`GameSession`を呼び、累計点・コンボ・直前イベント件数を表示します。
- 将来の変更: フェーズ4は`ResolvedTurn`を演出・得点内訳表示へ利用できます。
- 移行作業: 盤面操作だけが必要な呼び出しは`GameState`を継続利用できます。ルール込みの通常進行は`GameSession`へ切り替えます。

## 確認事項

フェーズ4では`ResolvedTurn`を使い、役名、カン、ドラ公開、得点理由を画面へ段階的に表示します。
