# ADR-0004: 7バッグ方式と壁蹴りなしの盤面内配置を採用する

- 状態: 採用
- 日付: 2026-07-24
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ2
- 関連仕様: `docs/PROJECT_SPEC.md` の「5. ブロック」

## 背景

17個のテトリミノについて、形の偏りを抑える出現順、次表示、ホールド、回転時の境界挙動を確定する必要があります。各セルの牌は形と一緒に移動・回転しなければなりません。

## 決定

I/O/T/S/Z/J/Lを1個ずつ含む7種類のバッグをシャッフルし、使い切ってから次のバッグを生成します。次ブロックは3個表示し、ホールドは採用しません。

ブロックは盤面上端中央へ出現します。90度回転では形と牌位置を同じ座標変換へ通し、回転後の相対座標を左上原点へ正規化します。壁蹴りは行わず、現在原点のまま4セルすべてが8×8内に収まる場合だけ回転します。既存牌との衝突判定は行いません。

## 理由

- 7バッグにより長期間特定形が出ない偏りを抑えられます。
- seedを注入すれば盤面と出現順をテストで再現できます。
- 次3個は計画性を持たせつつ画面を圧迫しすぎません。
- 壁蹴りなしはフェーズ2の境界規則を単純かつ明示的にできます。
- 牌付きセルを直接回転するため、形だけ回って牌配置が残る不整合を防げます。

## 検討した代替案

### 17個を完全ランダムに選ぶ

- 利点: 実装が小さくなります。
- 欠点: 形が大きく偏り、計画性が偶然に左右されます。
- 不採用理由: 7バッグ方式が承認されたためです。

### 壁蹴りを実装する

- 利点: 盤面端でも回転しやすくなります。
- 欠点: 壁蹴り候補の優先順という未確定ルールが増えます。
- 不採用理由: フェーズ2では過剰であり、その場で収まる場合だけ回転する方が明確なためです。

## 影響

- コード: `tetromino.py`が形、回転、7バッグを、`game.py`が位置を管理します。
- テスト: 全7形×4回転、牌位置、境界、バッグごとの7種を確認します。
- UI: 次3形と各セルの牌色を表示します。
- 将来の変更: ホールドや壁蹴りを追加する場合は入力と状態APIの拡張が必要です。
- 移行作業: なし。

## 確認事項

ホールドや高度な回転補正はプレイテスト後に必要性を再評価します。
