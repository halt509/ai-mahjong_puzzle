# ADR-0006: 固定座標の仮牌アトラスと麻雀テーマを採用する

- 状態: 採用
- 日付: 2026-07-24
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ4
- 関連仕様: `docs/PROJECT_SPEC.md` 17.3

## 背景

フェーズ2・3の文字中心の牌表示は動作確認には十分だったが、牌種の判別とゲーム全体の印象がテトリス寄りだった。正式な牌素材は後から用意する予定であり、今のUI実装を特定画像へ密結合させず、見た目の叩き台を用意する必要がある。

## 決定

34牌種を、Pyxel画像バンク0の16×16固定グリッドへ割り当てる。萬子、筒子、索子を各1行、字牌を1行に置く。

フェーズ4では実行時にコードで仮アトラスを生成する。実際の仮アトラス見本を`assets/sprites/mahjong-tiles-placeholder.png`、正式素材向けの方向案を`assets/concepts/mahjong-tile-sprite-concept.png`へ置く。

風牌は16×16枠でも確実に判別できるよう、東を右、南を下、西を左、北を上の矢印で描く。三元牌は白を白、發を緑、中を赤の牌面塗りつぶしで描く。索子などの暗い細部が配置先によって欠けないよう、透明色は暗い描線と異なるパレット番号を使う。ドラ表示牌も同じアトラスから描画する。

色は深い緑、木、象牙、朱、金、藍、竹色の16色パレットを用いる。画面の論理解像度は256×176を維持する。

## 理由

- `TileType`から画像座標への対応が一か所に集まり、正式素材への交換が盤面ロジックへ影響しない。
- 16×16の実寸で可読性と画面密度を早い段階で確認できる。
- 現在のウィンドウサイズと操作感を変えずに、麻雀卓らしいトーンへ寄せられる。
- コード生成の仮素材なので、正式素材が未完成でもリポジトリだけで再現できる。

## 検討した代替案

### 文字表示を継続する

- 利点: 実装が最小。
- 欠点: 牌らしさと判別性を確認できず、正式素材との接続境界も未検証になる。
- 不採用理由: フェーズ4のUI確認とユーザー要望を満たさない。

### 正式画像を先に確定する

- 利点: 最終品質に近い画面を作れる。
- 欠点: 素材準備と細部のアート判断がフェーズ4の機能確認を止める。
- 不採用理由: 正式素材は後から用意する方針であり、今回の範囲を超える。

## 影響

- コード: `sprites.py`がアトラス座標と仮描画を担当し、`app.py`は座標APIだけを使う。
- テスト: 34種すべてに一意の座標があることを検証する。
- UI: 盤面、タイトルの見本牌を同じアトラスで描く。
- 将来の変更: 同じ座標と透明色を守れば、画像バンクの読み込みへ交換できる。
- 移行作業: 正式素材完成時に仮生成をリソース読み込みへ置き換える。

## 確認事項

仮牌はデザインの完成品ではない。正式素材作成時に、16×16で萬子・索子・字牌が十分に区別できるかを再確認する。
