# ADR-0008: Web Launcherでフェーズ4を簡易公開確認する

> スマートフォン確認の対象範囲と入力方針は、2026-07-25のADR-0009で更新した。

- 状態: 採用
- 日付: 2026-07-24
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ4の公開前確認
- 関連仕様: `docs/PROJECT_SPEC.md` 17.5

## 背景

フェーズ5の内容を決める前に、フェーズ4までのゲームを他の人がインストールなしで試せる状態にしたい。正式なWebサイトやスマートフォン操作まで作ることは今回の目的ではない。

デスクトップ版は最高得点をローカルJSONへ保存するが、ブラウザでは同じファイル保存を永続化手段として扱えない。また、開発リポジトリ全体をPyxelアプリへ含めると、テストや開発用指示まで公開される。

## 決定

Pyxel Web Launcherで実行する`web/mahjong-puzzle.pyxapp`を生成する。

`scripts/build_web.py`は一時ディレクトリへ実行コードだけを集め、Pyxel 2.9系の`package`コマンドを呼び出す。配布物には`mahjong_puzzle`パッケージと引数なしの`web_main.py`だけを含める。

Web版では実行環境を`sys.platform == "emscripten"`で判別し、ブラウザの`localStorage`へ最高得点を保存する。デスクトップ版は既存のローカルJSON保存を維持する。

確認対象は物理キーボードを使えるPCブラウザとする。配布物のpushやリポジトリの公開状態変更は、ユーザーから別途明示されるまで行わない。

## 理由

- Web Launcherは`.pyxapp`をGitHub URLから直接実行でき、簡易プレイテスト用のページ制作が不要。
- ルール・画面コードをWeb専用に書き直す必要がない。
- localStorageならサーバーなしで、同じブラウザの最高得点を再読込後も保持できる。
- 一時ステージング方式なら`egg-info`、テスト、仕様書、開発用指示を配布物から除外できる。
- PCブラウザへ限定することで、未設計のタッチ操作を先行実装しない。

## 検討した代替案

### app2htmlと静的ホスティング

- 利点: 単一HTMLとしてPyxelバージョンを固定し、GitHub Pagesやitch.ioで公開できる。
- 欠点: 公開ページと運用方法を決める必要がある。
- 不採用理由: 今回は簡易確認が目的であり、Web Launcherで十分。

### リポジトリのPythonファイルをWeb Launcherで直接実行する

- 利点: 配布物の生成が不要。
- 欠点: 複数モジュールの読込が遅く、起動パスの管理も必要。
- 不採用理由: Pyxel公式も複数ファイルでは`.pyxapp`を推奨している。

### デスクトップ版と同じJSON保存を使う

- 利点: 保存コードを変更しなくてよい。
- 欠点: ブラウザ再読込後の永続性を期待できない。
- 不採用理由: 簡易プレイテストでも個人の最高得点は維持したい。

## 影響

- コード: 保存境界へlocalStorage実装と環境別ファクトリを追加する。
- テスト: localStorage検証とpyxapp内容検査を追加する。
- UI: 変更なし。
- 将来の変更: 正式公開時にapp2html、GitHub Pages、itch.ioを再検討できる。
- 移行作業: Web配布前にビルドスクリプトを再実行し、生成物を更新する。

## 確認事項

- `.pyxapp`はZIP形式であり、同梱したPythonソースを閲覧できる。
- Web Launcherで共有するには、生成物がGitHubから公開取得できる必要がある。
- スマートフォン操作とオンラインランキングは今回確認しない。
