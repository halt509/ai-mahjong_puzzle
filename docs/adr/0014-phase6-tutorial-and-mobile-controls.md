# ADR-0014: 初回説明を独立状態・独立保存として追加する

- 状態: 採用
- 日付: 2026-07-27
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ6
- 関連仕様: `docs/PROJECT_SPEC.md` の20節

## 背景

初めて遊ぶ人が外部画像を見なくても基本和了、再和了、カン、ドラを理解できる導線が必要になった。同時に、スマートフォンではプレイ中に`Y`の役一覧を誤って開きやすく、操作の割り当てを整理する必要がある。初回説明の既読状態を、後続フェーズで単位移行を予定しているハイスコア形式へ混ぜると、無関係な移行が結合してしまう。

## 決定

説明本文とページ位置をPyxel入力から独立した`tutorial.py`へ置き、画面状態へ`HELP`を追加する。初回表示と再閲覧は同じ4ページを使い、端末ごとの操作補足だけ描画時に切り替える。

既読状態は`TutorialProgressBackend`で分離する。デスクトップは`tutorial.json`、Webは`localStorage`の`ai_mahjong_puzzle.tutorial_seen`へ`{"seen": true}`を保存する。最後まで読んだ場合とスキップした場合の両方を既読とする。

スマートフォンは`START`をプレイ中の役一覧へ、`SELECT` / `BACK`を川へ、`A`を決定へ割り当て、`Y`は未割り当てにする。タイトル・結果画面の`START`は説明を開く。PCの既存キーは維持し、`H`だけ説明表示として追加する。

## 理由

- 説明内容を両レイアウトで共有しつつ、狭い縦画面だけ改行と操作補足を調整できる。
- 画面遷移とページ状態を入力・描画から分け、自動テストしやすい。
- 既読状態をハイスコアから分けることで、フェーズ7の得点単位移行に影響しない。
- `Y`を空けたままにし、将来機能を先回りして割り当てない。

## 検討した代替案

### ハイスコアJSONへ既読フラグを追加する

- 利点: 保存ファイルを1つにできる。
- 欠点: 得点データとUI進捗の破損・移行・書き込み責務が結合する。
- 不採用理由: フェーズ7で予定するハイスコア移行を局所化するため。

### 操作しながら学ぶ強制チュートリアル

- 利点: 実際の操作を確実に体験できる。
- 欠点: 専用盤面、進行制限、成功判定が必要になり、ゲームルールや開始処理へ影響する。
- 不採用理由: フェーズ6は短い初心者導線に限定し、コアゲームを変更しないため。

## 影響

- コード: `tutorial.py`、`ScreenMode.HELP`、初回説明保存境界、端末別操作補足を追加する。
- テスト: 4ページ内容、ページ境界、初回表示、スキップ保存、再閲覧、ファイル・Web保存、新しいゲームパッド割り当てを確認する。
- UI: 説明・通知・結果を日本語化し、狭い通常情報欄は英数表記で整理する。くじゃく絵文字を参考にした40×40の仮ピクセルスプライトと、実ゲーム画面から原寸で切り抜いた盤面を表示する。
- 将来の変更: 正式キャラクター素材は描画関数の置き換えで対応する。得点移行は既存のハイスコア保存だけを対象にできる。
- 移行作業: 既存利用者も`tutorial.json`またはWebキーを持たないため、更新後の最初の1回だけ説明が表示される。

## 確認事項

PC横画面とスマートフォン縦画面で全4ページと原寸の盤面切り抜きが枠内に収まること、くじゃく仮スプライトが識別できること、通常情報欄の文字がはみ出さないこと、`START`で役一覧を誤タップしにくくなったこと、タイトル・結果から説明を読み直せることを確認する。
