# ADR-0015: 得点単位を10倍しハイスコアをバージョン移行する

- 状態: 採用
- 日付: 2026-08-04
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ7
- 関連仕様: `docs/PROJECT_SPEC.md` の「12. 得点」「21. フェーズ7の得点単位とハイスコア移行」

## 背景

従来の得点は基本和了50点を基準としており、相対バランスは保てていたが、麻雀の点棒を扱う感覚として数字の単位が小さかった。全加点値を10倍する際、既存のハイスコアをそのまま残すと新旧の得点を比較できず、起動のたびに変換すると値が繰り返し増える。

## 決定

`ScoringConfig`の基本和了点、全役点、ドラ点、複合役ボーナス、同一行の再和了ボーナスを従来値の10倍とする。連続和了倍率、複数行同時和了倍率、端数処理は変更しない。

ハイスコアJSONへ`score_unit_version`を追加し、現行を`2`とする。バージョン情報がない旧形式と明示的なバージョン`1`は、読込時に得点を10倍してバージョン`2`で保存する。デスクトップとWebの保存境界がそれぞれ同じ規則を実装する。

## 理由

- すべての加点値を一律に変えることで、既存の役選択や倍率のバランスを維持できる。
- 保存データ自身に単位バージョンを持たせれば、環境や起動回数に依存せず一度だけ移行できる。
- 既存の保存キーとファイルを維持するため、ユーザー操作なしで最高得点を引き継げる。
- 保存境界内で移行することで、UIとルールエンジンへ保存形式の分岐を持ち込まずに済む。

## 検討した代替案

### 旧ハイスコアを破棄する

- 利点: 移行処理が不要。
- 欠点: 既存プレイヤーの記録が失われる。
- 不採用理由: 単位だけが変わるため、相対的に同じ記録として引き継げる。

### 起動時に常に10倍する

- 利点: 保存形式を変更しなくてよい。
- 欠点: 起動のたびに二重、三重に変換される。
- 不採用理由: 移行済みかを安定して判定できない。

### 新しい保存キー・ファイルへ分離する

- 利点: 新旧データを物理的に分離できる。
- 欠点: 旧保存先の探索と同期が必要になり、Webとデスクトップで移行経路が増える。
- 不採用理由: 同一ペイロードのバージョン管理で十分に安全に識別できる。

## 影響

- コード: `scoring.py`の既定値と`persistence.py`の保存ペイロードを変更する。
- テスト: 全加点値、倍率維持、PCファイル移行、Web `localStorage`移行、二重移行防止、不正バージョンを確認する。
- UI: 同じ表示項目の数値が10倍になる。点棒アイコンは後続作業とする。
- 将来の変更: 得点単位を再変更する場合は新しいバージョン番号と明示的な移行規則を追加する。
- 移行作業: 初回読込時に自動実行し、ユーザー操作は不要。

## 確認事項

旧ハイスコアが初回起動で10倍になり、再読込後も同じ値であることをPC版とWeb版で確認する。正式ビジュアル、BGM、開始演出、点棒表示はフェーズ7の後続作業で扱う。
