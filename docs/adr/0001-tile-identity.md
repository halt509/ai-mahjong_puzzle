# ADR-0001: 牌種と物理牌個体を分離する

- 状態: 採用
- 日付: 2026-07-24
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ1
- 関連仕様: `docs/PROJECT_SPEC.md` の「4. 牌」「15. 第1フェーズ」

## 背景

役、面子、ドラは同じ種類の牌を同値として扱う一方、136枚の総数確認や後続フェーズの上書き追跡では同種4枚を個別に識別する必要があります。

## 決定

不変な`TileType`を牌種、同じく不変な`Tile`を物理牌として分離します。`Tile`は`TileType`と0〜3の複製番号を持ち、`m1-1`のような安定した個体IDを自動生成します。ルール関数は`Tile`と`TileType`のどちらも受け取り、判定前に牌種へ正規化します。物理牌入力時は重複IDを拒否し、どちらの入力でも同一牌種5枚以上を拒否します。

## 理由

- 牌種比較と物理個体追跡の責務を混ぜずに済みます。
- 役判定を個体IDから独立させられます。
- 生成規則が決定的で、136枚の不足・重複をテストできます。
- 後続フェーズで牌の移動元と移動先を同じIDで追跡できます。

## 検討した代替案

### 文字列IDだけで牌種も表す

- 利点: データ構造が1つで済みます。
- 欠点: 役判定のたびに文字列を解析し、牌種同値性と個体同一性を混同しやすくなります。
- 不採用理由: 責務分離と入力検証が弱くなるためです。

### 牌種だけを持ち、個体IDは後続フェーズで追加する

- 利点: フェーズ1の型が小さくなります。
- 欠点: 136枚の個体ID一意性というフェーズ1要件を満たせません。
- 不採用理由: 必須テストと将来の牌総数追跡に必要なためです。

## 影響

- コード: `tiles.py`が牌種、物理牌、正規化の責務を持ちます。
- テスト: 34牌種各4枚、全136個体ID、重複ID、不可能な5枚入力を確認します。
- UI: フェーズ1では影響しません。
- 将来の変更: 表示名を変えてもASCII個体IDと牌種比較を維持できます。
- 移行作業: なし。

## 確認事項

第2フェーズで盤面、ドラ予約、ブロックへ配る際も、生成済み`Tile`の個体IDを再発行せず引き継ぎます。
