# ADR-0010: 共通ゲームからスマートフォン縦画面版を配布する

- 状態: 採用
- 日付: 2026-07-25
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ4の公開前確認
- 関連仕様: `docs/PROJECT_SPEC.md` 17.5

## 背景

ADR-0009ではPCとスマートフォンで横画面版を共有し、実端末で操作性を確認することにした。iPhoneの縦向き表示では、256×176のゲーム画面内で盤面と右側情報欄が横に並ぶため、盤面が端末幅の半分程度になった。また、画面上下に余白が多く、遊ぶために端末を横向きへ持ち替える必要があった。

一方、ルール、ゲーム状態、入力、牌スプライト、保存処理は端末によって変える必要がない。画面全体を別実装にすると二重保守になる。

## 決定

`MahjongPuzzleApp`へ横画面と縦画面のレイアウト種別を追加する。PC版は既存の256×176と盤面右側の情報欄を変更しない。スマートフォン版は176×256とし、128×128の盤面を上部中央、得点・ドラ・NEXT・川を盤面下に配置する。

タイトル、通知、川一覧、役一覧、結果画面にも縦画面用の描画を用意する。ゲーム状態、操作アクション、牌描画、効果音、ハイスコア保存は同じ実装を共有する。

Web配布物は次の2つに分ける。

- `web/mahjong-puzzle.pyxapp`: PC横画面版
- `web/mahjong-puzzle-mobile.pyxapp`: スマートフォン縦画面版

スマートフォン版だけが`LayoutMode.PORTRAIT`を指定する専用エントリを持つ。バーチャルゲームパッドは引き続きPyxel Web Launcherの`gamepad=enabled`を使用する。

## 理由

- 縦向きの端末幅を盤面へ有効に使え、牌の表示サイズを維持できる。
- 右側情報欄を盤面下へ移すことで、画面の横方向の空きを減らせる。
- PC版の表示と操作へ影響を与えずに公開できる。
- 差分を描画座標と起動エントリへ限定し、ゲームロジックの二重保守を避けられる。
- URLを分けることで、端末判定や自動回転に依存せず利用者が適切な画面を選べる。

## 検討した代替案

### 1つの配布物で端末を自動判定する

- 利点: 共有URLを1つにできる。
- 欠点: Pyxelアプリ起動後の論理解像度切り替えと端末判定が複雑になり、判定誤りを利用者が修正しにくい。
- 不採用理由: 簡易公開確認では、明示的なPC用・スマートフォン用URLの方が挙動を確認しやすい。

### PC版の画面も縦向きへ変更する

- 利点: 描画レイアウトを1種類にできる。
- 欠点: 既に確認済みのPC版の画面構成が変わり、横長ディスプレイで余白が増える。
- 不採用理由: ユーザーはPC版を維持し、スマートフォン版だけを最適化する方針を選んだ。

### 牌サイズを縮小して横画面を維持する

- 利点: レイアウト変更が小さい。
- 欠点: 風牌や索子を含む牌の視認性がさらに下がる。
- 不採用理由: 16×16の牌スプライトを維持し、盤面そのものを見やすくする。

## 影響

- コード: `app.py`へレイアウト種別と縦画面描画を追加し、`mobile_web_main.py`を追加する。
- テスト: PC版の既存寸法維持、縦画面寸法と盤面中央配置、専用配布物の内容を確認する。
- UI: スマートフォン版では盤面右の情報欄を廃止し、盤面下へまとめる。
- 将来の変更: 画面共通部分を変更する場合は、横・縦の両描画を確認する。
- 移行作業: ビルドスクリプトで2つの`.pyxapp`を生成し、スマートフォン用URLは`mahjong-puzzle-mobile`を指定する。

## 確認事項

- iPhone SafariとAndroid Chromeで、縦向きの盤面サイズと情報欄の読みやすさを確認する。
- タイトル、通知、川一覧、役一覧、結果画面が画面からはみ出さないことを確認する。
- バーチャルゲームパッドがゲーム画面を隠さないことを確認する。
- PC版の256×176画面が従来どおりであることを確認する。
- 盤面への直接タッチ操作、オンラインランキング、端末間同期は今回の対象外とする。
