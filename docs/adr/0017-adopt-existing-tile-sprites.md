# ADR-0017: 既存の16×16牌スプライトを正式採用する

- 状態: 採用
- 日付: 2026-08-05
- 使用AIモデル: GPT-5 / OpenAI組み込み画像生成
- 関連フェーズ: フェーズ7
- 関連仕様: `docs/PROJECT_SPEC.md` 21.5

## 背景

フェーズ4では、34種の牌を16×16で見分けられるコード生成スプライトを実装した。フェーズ7ではAI生成の方向案を参考に、牌面の面取り、厚み、萬子の字形、筒子と索子の模様を変更した固定PNGを試作し、PCとスマートフォンの実ゲーム画面で比較した。

試作では牌面を内側へ狭めた一方、模様が従来と同じ範囲を使ったため、一部の絵柄が右下の影へ乗って見えた。また、筒子と索子は従来表示より判別しにくくなった。

## 決定

- フェーズ7の固定PNG試作はゲームへ採用しない。
- フェーズ4から使用していたコード生成の16×16牌スプライトを、ゲームの正式な牌表示として採用する。
- 盤面、ドラ、タイトル、役一覧、チュートリアル、初心者向けガイドは同じ採用牌へ揃える。
- `build_placeholder_tile_atlas()`という既存の関数名は公開済みコードとテストへの影響を避けるため維持するが、生成内容は仮表示ではなく採用表示として扱う。
- 固定座標と透明色の境界は維持し、牌表示をゲームルールや画面レイアウトから分離する。
- AI生成の方向案は牌へ使用せず、キャラクターと点棒UIの参考に限定する。

## 理由

16×16では装飾量よりも、盤面上で牌種を即座に見分けられることと、牌面と影の境界が崩れないことを優先する。既存表示はPCとスマートフォンのテストプレイで十分な視認性が確認されており、実行時生成なので配布用PNGの欠落も起きない。

## 検討した代替案

### 固定PNG試作を牌種ごとに修正する

- 利点: 新しい面取りと萬子の字形を残せる。
- 欠点: 16×16で模様と影が使える領域が狭く、筒子・索子の視認性も再調整が必要になる。
- 不採用理由: 比較結果として、従来表示の方がゲーム中に読みやすかったため。

### 牌サイズを拡大する

- 利点: 漢字や装飾を精密に描ける。
- 欠点: 8×8盤面、情報欄、PC・スマートフォン両レイアウトの再設計が必要になる。
- 不採用理由: 今回の牌表示調整の範囲を超えるため。

## 影響

- コード: アプリ起動時に`build_placeholder_tile_atlas()`で画像バンク0へ牌を生成する構成へ戻る。
- 配布物: 正式牌試作PNGをPC・スマートフォンWeb版へ同梱しない。
- UI: 牌の外枠、萬子、筒子、索子、風牌、三元牌がフェーズ4からの表示へ戻る。
- 文書: 従来牌を「仮牌」ではなく、比較確認後に選んだ採用牌として扱う。

## 確認事項

- PC・スマートフォンの盤面で、絵柄が牌の影へ乗っていないことを確認する。
- 萬子1〜9、筒子1〜9、索子1〜9、風牌、三元牌を見分けられることを確認する。
- チュートリアルと初心者向けガイドがゲーム画面と同じ牌を表示することを確認する。
