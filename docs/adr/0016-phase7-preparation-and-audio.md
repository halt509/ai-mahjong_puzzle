# ADR-0016: 開始準備状態とBGM・効果音チャンネルの分離

- 状態: 採用
- 日付: 2026-08-04
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ7
- 関連仕様: `docs/PROJECT_SPEC.md` 21.3、21.4

## 背景

ゲーム開始と再スタートを視覚・聴覚で明確にしつつ、プレイ中のBGMと配置、カン、和了などの効果音を同時に聞き分けられる構成が必要になった。既存の画面状態には準備中を表す状態がなく、効果音もPyxelの全4チャンネルを使用していたため、BGMを継続再生する境界を決める必要があった。

## 決定

- `UiState`へ`PREPARING`を追加し、タイトル開始と結果画面からの再スタートは、約1.4秒の準備状態を経て`GAME`へ移る。
- 準備中は「雀卓清掃中」、開始・再スタート別の補足、動く牌の背を表示し、開始時に短い牌混ぜ効果音を再生する。
- BGM専用にチャンネル3を予約し、配置、カン、和了、結果、牌混ぜの効果音はチャンネル0〜2へ集約する。
- BGMは準備完了時に開始し、結果確定時と次の準備開始時に停止する。
- 遊び方画面の`M` / `BACK`に加え、プレイ中は川画面の`Space` / `Enter` / `A`でBGMを切り替える。`Y`は割り当てない。
- BGMは低音と休符を中心にした遅いフレーズとし、各音の音量を2以下へ抑える。
- ミュート状態は起動中だけ保持し、保存データへは追加しない。

## 理由

準備状態を独立させると、ゲーム入力を誤って受け付けず、開始と再スタートの遷移を同じ仕組みで表現できる。BGMのチャンネルを予約すれば、効果音によるBGMの中断を避けながら、Pyxelの4チャンネル内で責務を明確にできる。ミュートを保存しないことで、この段階では永続化形式を増やさず、後から音量設定全体を検討できる。

## 検討した代替案

### 既存のゲーム画面へ準備表示を重ねる

- 利点: 画面状態を増やさずに済む。
- 欠点: 準備中の入力抑止とゲーム開始タイミングが描画側へ混ざり、再スタートの切り替わりも曖昧になる。
- 不採用理由: 画面遷移の責務が不明確になるため。

### BGMと効果音で全チャンネルを共有する

- 利点: 既存の効果音チャンネルを変更しなくてよい。
- 欠点: 効果音再生時にBGMの一部が途切れ、聞き分けにくくなる。
- 不採用理由: フェーズ7の完了条件であるBGMと効果音の両立を安定して満たせないため。

## 影響

- コード: `UiState`に準備状態を追加し、アプリに準備タイマー、BGM制御、専用チャンネル構成を追加する。
- テスト: 開始・再スタート遷移、準備表示、BGM開始・停止、ミュート、`Y`未割り当てを回帰確認する。
- UI: PC横画面とスマートフォン縦画面に同系統の準備画面を表示し、遊び方画面と川画面にBGM状態を表示する。
- 将来の変更: 音量設定やミュート永続化が必要になった場合は、独立した設定保存として追加できる。
- 移行作業: 既存保存データの変更はない。

## 確認事項

- 牌混ぜ音と準備時間がプレイテンポに合うかを実機で確認する。
- BGM中も配置、カン、和了の効果音が聞き分けられるかを確認する。
- 正式ビジュアルと点棒表示はフェーズ7の後続作業へ持ち越す。
