# ADR-0002: 最小牌を起点とした多重集合バックトラッキングで全分解する

> 2026-07-25: 通常形とは異なる四対子の分解表現は、ADR-0011で追加した。通常の「3＋3＋2」分解アルゴリズムは引き続き本ADRに従う。

- 状態: 採用
- 日付: 2026-07-24
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ1

## 背景

8牌を順不同で「3枚組＋3枚組＋2枚組」へ分解し、複数候補を漏らさず返す必要があります。同じ牌を重複使用してはならず、同一牌4枚も4枚面子ではなく通常の多重集合として扱う必要があります。

## 決定

牌種ごとの`Counter`を作り、対子候補を全列挙します。対子を2枚引いた後、残りの最小牌を必ず含む刻子と順子をそれぞれ試すバックトラッキングで2面子を列挙します。各分岐で実際に枚数を減らし、戻る際に復元します。結果は不変な`HandDecomposition`として重複排除し、安定順で返します。

## 理由

- 8牌という小さな固定入力では探索量が十分小さいです。
- 最小牌を必ず消費するため、無関係な組合せを試さず全候補を列挙できます。
- `Counter`の減算で牌の重複使用を構造的に防げます。
- 4枚同一牌にも特別な面子規則を設けず、刻子や別用途へ通常どおり振り分けられます。
- 入力順に依存せず、結果順も決定的です。

## 検討した代替案

### 8牌の全順列を調べる

- 利点: 発想が単純です。
- 欠点: 同一牌による重複探索が多く、入力順や結果順の扱いも複雑になります。
- 不採用理由: 多重集合として直接処理する方が規則を読み取りやすいためです。

### 成立形を事前に全列挙して照合する

- 利点: 実行時の判定を単純化できます。
- 欠点: 候補生成、保守、役追加時の追跡が複雑になり、今回の小さな入力には過剰です。
- 不採用理由: 将来可能性だけを理由に大きな事前テーブルを持つ必要がないためです。

## 影響

- コード: `hand.py`が分解だけを担い、役判定は`yaku.py`に分離されます。
- テスト: 順子、刻子、混合、入力順、字牌、不成立、4枚牌、複数候補、全牌消費を確認します。
- UI: Pyxelや盤面への依存はありません。
- 将来の変更: 新しい役は分解結果を利用できますが、4枚面子を採用するルール変更ではアルゴリズム変更が必要です。
- 移行作業: なし。

## 確認事項

カンはこの分解へ組み込まず、`kan.py`で独立イベントとして判定し続けます。
