# ADR-0003: 136枚を64＋4＋68へ配分し17ターンとする

- 状態: 採用
- 日付: 2026-07-24
- 使用AIモデル: GPT-5
- 関連フェーズ: フェーズ2
- 関連仕様: `docs/PROJECT_SPEC.md` の「11. ドラ」「13. 136枚の配分」

## 背景

盤面、ドラ表示牌、配置ブロックが同じ136枚の物理牌を重複なく使用し、ゲーム終了まで牌総数を追跡できる配分を確定する必要があります。

## 決定

136枚を初期盤面64枚、ドラ表示牌用の予約4枚、配置ブロック用68枚へ分けます。配置牌は4枚ずつ17ブロックにし、17回の配置でゲーム終了とします。ゲーム開始時には予約の先頭1枚を公開し、未公開の予約牌は未使用牌として保持します。

配置のたびに盤面の4枚を川へ移し、ブロックの4枚を盤面へ入れます。盤面、川、未配置ブロック、ドラ予約にある全個体IDが常に重複なしの136枚であることを検証します。

## 理由

- 8×8盤面を最初から64枚で埋められます。
- 最大4枚のドラ表示牌を固定予約できます。
- 残り68枚を4枚ブロックへ余りなく分配できます。
- ターン終了条件が17配置と明確になります。
- 物理牌IDによる総数検査を全ターンで維持できます。

## 検討した代替案

### 必要時に牌山からドラ表示牌を引く

- 利点: カンが少ないゲームでは配置可能な牌を増やせます。
- 欠点: ゲームごとのブロック数と終了条件がカン回数に左右されます。
- 不採用理由: フェーズ2では固定17ターンの方が操作と総数を検証しやすいためです。

### 未公開予約牌をゲーム終了時に公開する

- 利点: 136枚すべてを画面上で公開できます。
- 欠点: 得点に使わない表示牌を公開する意味が分かりにくくなります。
- 不採用理由: 未使用牌として結果へ記録する方針が承認されたためです。

## 影響

- コード: `game.py`が配分、進行、牌総数検証を担います。
- テスト: 初期状態、各配置後、17ターン終了後の136個体IDを確認します。
- UI: ターン数を0/17から17/17まで表示します。
- 将来の変更: 配分を変える場合はターン数と終了条件も同時に変更します。
- 移行作業: フェーズ1の牌モデル変更はありません。

## 確認事項

カンによる予約牌の追加公開と結果画面での未使用牌表示は後続フェーズで接続します。
