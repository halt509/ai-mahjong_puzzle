# 1. ゲーム概要

8×8の盤面に最初から麻雀牌が配置されている。

プレイヤーは、複数の牌で構成されたテトリミノ型ブロックを盤面へ重ねて配置する。配置先に元からあった牌は盤面から取り除かれ、川へ捨てられる。

ブロックを配置した結果、**横方向の1行・8牌**が「面子2組＋対子1組」の和了形になり、かつ未取得の役を含んでいる場合、その行で和了が成立して得点を獲得する。

和了した行は消さず、そのまま盤面に残す。同じ行をさらに書き換え、別の役を含む和了形へ作り直すことで、同じ行で複数回和了できる。

ゲームの目標は、限られた136枚の牌を使い切るまでに、できるだけ高い得点を獲得することである。

---

# 2. ゲームの核

このゲームで中心になる判断は次のとおり。

- 現在の盤面にある牌をどこまで利用するか
- ブロックの回転によって、各行へどの牌を配るか
- どの牌を川へ捨てるか
- 簡単な役ですぐ和了するか、高い複合役まで待つか
- 同じ行を育てるか、複数の行を並行して整えるか
- カンでそのターンの和了を見送り、追加ドラを狙うか
- 連続和了や複数行同時和了を狙うか

---

# 3. 基本盤面

- 盤面サイズは8×8。
- ゲーム開始時点で全64マスに牌が配置されている。
- 和了判定は**横方向の8行**に対して行う。
- 縦方向の列では和了判定を行わない。
- ブロック配置によって1枚以上変更された行だけを、そのターンの判定対象にする。
- 初期配置だけで成立している役やカンは、自動では成立させない。
- 牌の盤面上での左右順は和了判定に影響しない。1行の8牌を集合として判定する。

---

# 4. 牌

通常の日本麻雀と同じ136枚を使用する。

- 萬子: 1〜9を各4枚
- 筒子: 1〜9を各4枚
- 索子: 1〜9を各4枚
- 風牌: 東・南・西・北を各4枚
- 三元牌: 白・發・中を各4枚

赤ドラは初期版では使用しない。

牌は内部的に一意のIDを持つ。同じ種類の牌4枚は牌種としては同一だが、デバッグや牌総数確認のため、個体IDでは区別できる設計にする。

---

# 5. ブロック

MVPでは、4牌で構成されるテトリミノを使用する。

- I / O / T / S / Z / J / L の7種類
- 90度単位で回転可能
- 反転は不可
- 各マスに1枚の牌を持つ
- 回転すると形と牌の位置が一緒に回転する
- 盤面内に収まれば配置可能
- 既存の牌との衝突判定は不要
- 上書きされた牌は川へ移動する

フェーズ2では次の設定を採用する。

- 出現順は、7種類を1回ずつ含む組をシャッフルする7バッグ方式
- 次ブロック表示は3個
- ホールド機能は使用しない
- 配置時に壁蹴りは行わず、回転後の4マスが盤面内に収まる場合だけ回転する

---

# 6. 川

川は、盤面から上書きされた牌を記録する領域とする。

## データとして必ず保持する内容

- 捨てられた牌
- 捨てられたターン
- 元の盤面座標
- どのブロック配置によって捨てられたか

## 画面表示

川を常時すべて表示すると画面がうるさくなる可能性が高いため、MVPでは次の表示を推奨する。

- 通常画面では直近8枚だけを小さく表示
- 合計の捨て牌数を併記
- `Tab`で川の全履歴をオーバーレイ表示

第1フェーズでは画面表示を作らず、データ構造だけを想定する。

---

# 7. 基本和了形

1行8牌を、次の形に分解できることを基本和了条件とする。

- 3枚組
- 3枚組
- 2枚組

3枚組として認めるもの:

- 順子: 同じ数牌種で数字が連続する3枚
- 刻子: 同一牌3枚

2枚組として認めるもの:

- 対子: 同一牌2枚

追加ルール:

- 字牌は順子を作れない。
- 数牌の9と1は連続しない。
- 牌の左右順は問わない。
- 同じ8牌に複数の分解方法がある場合、すべての有効な分解を列挙する。
- 得点計算時には、そのターンで最も得点が高くなる有効な分解を採用する。
- ドラだけでは和了できない。
- 基本和了形を満たしていても、認識対象の役が1つもなければ和了にはしない。

---

# 8. 初期採用役

最初の試作では役を増やしすぎず、次の8種類から開始する。

| 内部ID | 表示名 | 条件 |
|---|---|---|
| `all_sequences` | 全順子 | 2つの面子が両方とも順子 |
| `all_triplets` | 全刻子 | 2つの面子が両方とも刻子 |
| `tanyao` | 断么九 | 8牌すべてが2〜8の数牌 |
| `iipeikou` | 一盃口 | 2つの面子が同一の順子 |
| `honitsu` | 混一色 | 1種類の数牌と字牌だけで構成 |
| `chinitsu` | 清一色 | 1種類の数牌だけで構成 |
| `honroutou` | 混老頭 | 8牌すべてが1・9・字牌 |
| `yakuhai` | 役牌 | 白・發・中のいずれかを刻子として含む |

役名は麻雀を参考にしているが、8牌ルールに合わせた独自仕様として扱う。

役ごとの点数は設定ファイルまたは定数テーブルで管理し、ロジックへ直接書き込まない。

# 9. 同じ行での複数回和了

各行は、これまで取得した役を集合として保持する。

例:

```text
1行目の取得済み役:
- 清一色
- 全順子
```

現在成立している役の集合を `current_yaku`、その行の取得済み役を `acquired_yaku` とする。

```python
new_yaku = current_yaku - acquired_yaku
```

`new_yaku` が1つ以上ある場合だけ、その行で新しい和了が成立する。

## 例

1回目に「清一色＋全順子」を取得済みの場合:

| 次の成立役 | 判定 |
|---|---|
| 清一色 | 無効 |
| 全順子 | 無効 |
| 清一色＋全順子 | 無効 |
| 一盃口 | 有効 |
| 清一色＋一盃口 | 有効 |
| 全順子＋断么九 | 有効 |
| 清一色＋全順子＋一盃口 | 有効 |

有効な和了後は、現在成立したすべての役を取得済み役へ追加する。

```python
acquired_yaku |= current_yaku
```

役そのものの基本点は、新しく取得した役にだけ加算する。取得済み役も複合役数の判定には含めてよい。

# 10. カン

## 成立条件

ブロック配置後、変更された行に同一牌が4枚存在した場合、その行でカン候補が成立する。

次の条件を満たす場合、新規カンとして処理する。

- その行で、その牌種のカンを過去に成立させていない
- ドラ表示牌の上限に達していないかどうかに関係なく、カン履歴自体は記録する

## カン成立時の処理

- 新規カンが成立した行は、そのターンの和了判定を行わない。
- 新しいドラ表示牌を1枚公開する。
- カンそのものには得点を付けない。
- 同じターンに別の行で成立した和了は有効。
- 新しく公開したドラは、同じターンの別行の和了得点にも反映する。
- 1回の配置で複数行に新規カンが成立した場合、それぞれ処理する。
- 1行に複数種類の新規カンが同時成立した場合も、それぞれカンとして処理する。ただしドラ枚数は上限を超えない。

## カン後の和了判定

カンした4枚を、4枚組の面子として扱わない。

後のターンでその行が再び書き換えられた場合、8牌全体を通常どおり「3＋3＋2」に分解する。

同一牌4枚が残っている場合も、分解ロジック上は刻子3枚と余り1枚として利用できる可能性がある。4枚を自動的に1面子として扱ってはならない。

## 再カン防止

各行に、カン済みの牌種を記録する。

- 同じ行・同じ牌種のカンは二度成立しない。
- 別の行で同じ牌種を4枚そろえた場合は新規カンとして扱う。
- 同じ行でも別の牌種なら新規カンとして扱う。

---

# 11. ドラ

- ゲーム開始時にドラ表示牌を1枚公開する。
- 新規カンごとに追加のドラ表示牌を公開する。
- ドラ表示牌は合計最大4枚を暫定上限とする。
- 裏ドラは初期版では使用しない。
- カンドラ以外の追加ドラは使用しない。
- ドラは役ではなく、和了得点への追加点として扱う。
- ドラだけでは和了できない。
- 同じドラが複数回指定された場合、重複して数える。

## ドラ対応

- 数牌: 1→2→3→…→9→1
- 風牌: 東→南→西→北→東
- 三元牌: 白→發→中→白

---

# 12. 得点

得点値はすべて設定として差し替え可能にする。

推奨する計算構造:

```text
基本得点
= 新規取得役の点数
+ ドラ点
+ 複合役ボーナス
+ 同一行の累計和了ボーナス

最終得点
= 基本得点
× 連続ターン和了倍率
× 複数行同時和了倍率
```

## 得点上の原則

- 取得済み役の基本点は再加算しない。
- 現在の和了に含まれる役の総数は、複合役ボーナスに使用できる。
- 同じ行での和了回数に応じて加点する。
- 1回の配置で複数行が和了した場合、同時和了ボーナスを付ける。
- 連続するターンで和了した場合、連続和了コンボを加算する。
- カンだけが成立したターンは、連続和了コンボを増やさないが切らない。
- 和了もカンも成立しないターンで、連続和了コンボをリセットする。

仮の点数や倍率は第1フェーズで設定テーブルとして用意するが、ゲームバランスの確定値とはしない。

---

## 12.1 フェーズ3のターン解決順

同じ配置で複数行が変更された場合、行番号順に逐次確定してはならない。次の順でターン全体を解決する。

1. 配置後の全変更行について新規カンを検出し、行ごとのカン履歴へ記録する。
2. 全新規カンについて、表示牌上限まで追加ドラ表示牌を公開する。
3. 新規カンがある行は、このターンの和了判定から除外する。
4. その他の変更行について、未取得役を1つ以上含む和了候補を抽出する。
5. 和了行数とターンの連続和了数を確定する。
6. 同じターンに公開したカンドラを含め、各和了行の最高得点分解を採用する。
7. 取得済み役、行の和了回数、累計得点を更新する。

ドラ表示牌が上限に達していても、新規カンの履歴は記録する。同一行・同一牌種のカンが履歴済みの場合、その牌種は新規カンではないため、それだけを理由に和了判定を保留しない。

ターン結果は、配置結果、新規カン、公開表示牌、和了行、採用分解、現在役、新規役、ドラ枚数、得点内訳、コンボ、ターン得点、累計得点を構造化データとして保持する。

---

## 依頼内容

Pyxelで制作予定の麻雀風パズルゲームについて、第1フェーズとして、画面描画から独立したPython製のルール判定エンジンを実装してください。

今回はPyxelの画面、入力、音、画像、ブロック操作は実装しません。ルールロジックと自動テストだけを作成してください。

後続フェーズでPyxelへ接続しやすいように、描画処理やグローバル状態へ依存しない構成にしてください。

### ゲームの基本

- 盤面は8×8だが、第1フェーズでは1行8牌の判定を中心に実装する。
- 和了判定は横方向の行に対して行う。
- 牌の左右順は問わない。
- 基本和了形は「3枚組＋3枚組＋2枚組」。
- 3枚組は順子または刻子。
- 2枚組は対子。
- 字牌は順子にできない。
- 役が1つもない場合は和了として扱わない。
- ドラだけでは和了できない。

### 必要な実装

#### 1. 牌データモデル

通常の日本麻雀136枚を表現してください。

最低限、次を扱えるようにしてください。

- 萬子・筒子・索子
- 1〜9
- 東・南・西・北
- 白・發・中
- 牌種の比較
- ソート用の安定した順序
- 表示用文字列
- 同種4枚を個体として追跡できる一意ID

`create_full_tile_set()` のような関数で、重複や不足のない136枚を生成できるようにしてください。

#### 2. 和了形の分解

8牌を「3＋3＋2」に分解できるか判定してください。

- 順子・刻子・対子を使用する。
- 牌の入力順に依存しない。
- 有効な分解が複数ある場合は、すべて列挙する。
- 同一牌4枚を自動的に4枚組として扱わない。
- 同一牌4枚が含まれる場合も、3枚を刻子へ使い、残り1枚を別用途へ使う通常の多重集合として判定する。
- 再帰またはバックトラッキングを使って構わない。
- 入力の8牌を重複して使用してはならない。

#### 3. 役判定

最初は次の役を実装してください。

- `all_sequences`: 2面子が両方とも順子
- `all_triplets`: 2面子が両方とも刻子
- `tanyao`: 8牌すべてが2〜8の数牌
- `iipeikou`: 2面子が同一の順子
- `honitsu`: 1種類の数牌と字牌だけで構成
- `chinitsu`: 1種類の数牌だけで構成
- `honroutou`: 8牌すべてが1・9・字牌
- `yakuhai`: 白・發・中のいずれかを刻子として含む

1つの8牌に複数の有効分解がある場合、分解ごとの成立役を返してください。

#### 4. 行ごとの和了履歴

各行について、取得済み役を集合で保持する状態クラスを作成してください。

現在の成立役を `current_yaku`、取得済み役を `acquired_yaku` とした場合、

```python
new_yaku = current_yaku - acquired_yaku
```

が1つ以上ある場合だけ新規和了とします。

新規和了後は、現在成立しているすべての役を取得済みへ追加してください。

過去の役だけで構成された和了は無効にしてください。取得済み役を含んでいても、未取得役が1つ以上追加されていれば有効にしてください。

#### 5. カン判定

1行8牌に同一牌4枚が存在するか判定してください。

各行にカン済み牌種の履歴を持たせてください。

- 同じ行・同じ牌種のカンは二度成立しない。
- 同じ行でも別牌種のカンは成立する。
- 別の行なら同じ牌種でも成立する。
- 1行に複数種類の新規カンがある場合、すべて返す。
- 新規カンが存在する行は、そのターンの和了判定を保留する設計にする。

カン自体は4枚組の面子ではありません。

#### 6. ドラ

ドラ表示牌から実際のドラを求める関数を実装してください。

- 数牌は9の次が1
- 風牌は東→南→西→北→東
- 三元牌は白→發→中→白
- 複数のドラ表示牌に対応
- 同じドラが複数指定された場合は重複して数える
- 1行の和了牌に含まれるドラ枚数を数える

裏ドラ、赤ドラは実装しないでください。

#### 7. 得点

得点は設定テーブルから変更可能にしてください。

次の要素を分けて計算できる設計にしてください。

- 新規取得役の点数
- ドラ点
- 複合役ボーナス
- 同じ行の累計和了ボーナス
- 連続ターン和了倍率
- 複数行同時和了倍率

現段階の数値は仮で構いません。数値をロジックへ直接埋め込まず、設定クラスまたは定数テーブルへまとめてください。

得点結果は合計値だけでなく、内訳を構造化データで返してください。

#### 8. ターン状態

画面や盤面操作には依存しない、最低限のターン状態を作成してください。

- 現在の連続和了数
- カンだけのターンではコンボを維持する
- 和了ターンではコンボを増やす
- 和了もカンもないターンではコンボをリセットする
- 同時和了した行数を得点計算へ渡せる

- 個体IDが重複しない

#### 和了形

- 順子＋順子＋対子で和了できる
- 刻子＋刻子＋対子で和了できる
- 順子＋刻子＋対子で和了できる
- 入力順がランダムでも同じ判定になる
- 字牌を順子として扱わない
- 不成立の8牌を和了扱いしない
- 同一牌4枚を4枚組の面子として扱わない
- 複数の分解方法がある場合に全候補を返す
- 同じ牌を複数の面子へ重複使用しない

#### 役

- 各初期役の成立例
- 各初期役の不成立例
- 複合役をすべて返す
- 役がない基本形を和了扱いしない
- 複数分解ごとに役が正しく異なるケース

#### 再和了

- 初回の役を取得できる
- 取得済み役だけでは再和了できない
- 取得済み役を含んでも新規役があれば再和了できる
- 和了後に取得済み役が更新される
- 得点対象が新規役だけになる

#### カン

- 同一牌4枚を新規カンとして検出する
- 同じ行・同じ牌種では再カンしない
- 同じ行の別牌種なら新規カンになる
- 別の行なら同じ牌種でも新規カンになる
- 1行に2種類の新規カンがある場合に両方返す
- 新規カンのある行で和了判定を保留できる

#### ドラ

- 数牌9の次が1になる
- 北の次が東になる
- 中の次が白になる
- 複数ドラを数えられる
- 同じドラ指定が重複加算される

#### 得点・コンボ

- 新規役だけが基本点へ加算される
- 取得済み役も複合役数には含められる
- ドラ点が加算される
- 同一行和了回数ボーナスが加算される
- 複数行同時和了倍率が適用される
- 和了ターンでコンボが増える
- カンだけのターンでコンボが維持される
- 失敗ターンでコンボがリセットされる

# 17. フェーズ4で確定したUIと演出

## 17.1 画面構成

- タイトル、ゲーム、結果の3画面を持つ。
- ゲーム画面から`Tab`で川の全履歴、`Y`で役一覧をオーバーレイ表示する。
- ゲームの論理解像度は256×176を維持する。
- 結果画面には得点、ハイスコア、ターン数、和了数、カン数、取得役種数、川の牌数を表示する。
- 結果画面から`R`で新しいゲームを開始する。

## 17.2 通知

- 1ターンに複数のカン・和了がある場合は、ターン解決結果の安定順で1件ずつ通知する。
- カン通知は成立した行と牌種、追加公開したドラ表示牌を示す。
- 和了通知は成立役、新規役、ドラ枚数、獲得点を示す。
- 通知中に操作キーが押された場合、その通知を閉じる。
- 通知を閉じた入力は盤面操作へ流用せず、次の入力から通常操作へ戻る。
- 最終ターンの通知をすべて閉じた後に結果画面へ移る。

## 17.3 牌と配色

- 34種の牌を16×16の固定アトラス座標へ対応付ける。
- フェーズ4ではコード生成の仮牌を使用し、正式スプライトは同じ座標へ後から交換できる。
- 風牌は東を右、南を下、西を左、北を上の矢印で示す。
- 三元牌は白を白、發を緑、中を赤の牌面塗りつぶしで示す。
- 透明色は牌面の暗い描線と異なる色番号を使用する。
- 配色は深い緑の麻雀卓、木枠、象牙色の牌を基調に、朱、金、藍、竹色をアクセントとする。
- ゲーム画面のドラ表示牌は文字ラベルではなく同じ牌スプライトで表示する。
- 仮アトラス見本と正式素材向けのビジュアル方向案を`assets/`へ保存する。

## 17.4 音と保存

- 配置、カン、和了、結果の効果音をPyxelの音色・音列で生成する。
- ハイスコアはローカルJSONへ非負整数の最高得点だけを保存する。
- 保存データが破損している場合は黙って上書きせず、画面へ保存不可を表示してゲームを継続する。
- ランキング、複数プロフィール、クラウド同期はフェーズ4に含めない。

## 17.5 フェーズ4の簡易Web確認

- ゲーム機能を追加するフェーズ5とは分け、フェーズ4の公開前確認として扱う。
- Pyxel Web Launcherで実行できる`.pyxapp`を生成する。
- Web確認対象はキーボードを使えるPCブラウザとする。
- Web版の最高得点はブラウザの`localStorage`へ保存する。
- デスクトップ版の最高得点は従来どおりローカルJSONへ保存する。
- Web配布物には実行に必要なPythonコードだけを含める。
- `.pyxapp`内のPythonソースは閲覧可能であることを公開前に確認する。
- スマートフォン、タブレット、バーチャルゲームパッド、オンラインランキング、端末間同期は対象外とする。
