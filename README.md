# AI Mahjong Puzzle

作成日・更新日: 2026-07-24<br>
使用AIモデル: GPT-5

Pyxelで制作する8×8牌上書きパズルゲームです。フェーズ1の純粋Pythonルール判定エンジンに加え、フェーズ2として盤面、テトリミノ操作、牌の上書き、川、ターン進行、確認用Pyxel画面まで実装しています。

フェーズ1の和了・カン・ドラ・得点を配置ターンへ統合する処理はフェーズ3の範囲であり、まだ画面へ接続していません。

## 必要環境とセットアップ

- Python 3.11以降
- Pyxel 2.9以上、3未満
- テスト時のみpytest

PowerShellで次を実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
```

## フェーズ2画面の起動

```powershell
python -m mahjong_puzzle.app
```

同じ盤面とブロック順を再現する場合はseedを指定できます。

```powershell
python -m mahjong_puzzle.app --seed 20260724
```

インストール後は次のコマンドでも起動できます。

```powershell
mahjong-puzzle
```

### 操作

| キー | 操作 |
|---|---|
| 矢印キー | ブロックを上下左右へ移動 |
| `Z` | 反時計回りに90度回転 |
| `X` | 時計回りに90度回転 |
| `Space` / `Enter` | 現在位置へ配置 |
| `Esc` | 終了 |

盤面の黄色い4マスが配置プレビューです。既存牌との衝突はなく、その位置の牌を上書きします。17個のブロックをすべて配置すると終了です。

画面ではPyxel組み込みフォントを使うため、数牌を`m1`・`p9`・`s5`、字牌を`E/S/W/N/P/F/C`で表示します。

## フェーズ2の確定設定

- 136枚を初期盤面64枚、ドラ表示牌用4枚、配置ブロック用68枚へ配分
- 4牌ブロック17個、全17ターン
- 未公開ドラ表示牌候補は未使用牌のまま保持
- 次ブロックを3個表示
- ホールドなし
- 7種類を1回ずつ含む7バッグ方式
- 川は上書き牌、ターン、元座標、配置IDの全履歴を保持

## 主要モジュール

- `tiles.py`: 牌種、一意ID付き物理牌、136枚生成
- `hand.py` / `yaku.py`: 3＋3＋2全分解と初期8役
- `kan.py` / `dora.py`: カン候補とドラ計算
- `scoring.py` / `state.py`: 得点内訳、行・コンボ状態
- `board.py`: 常に64枚を保持する8×8盤面と原子的上書き
- `tetromino.py`: 牌位置ごとの回転、7種類の形、7バッグ生成
- `river.py`: 捨て牌の全履歴
- `game.py`: 136枚配分、配置、ターン、終了、牌総数検証
- `app.py`: Pyxel描画と入力だけを担う画面アダプター

## 仮点数

点数は`ScoringConfig`へ集約してあり、ゲームバランス確定値ではありません。

| 要素 | 仮値 |
|---|---:|
| 全順子 | 100 |
| 全刻子 | 200 |
| 断么九 | 100 |
| 一盃口 | 200 |
| 混一色 | 300 |
| 清一色 | 500 |
| 混老頭 | 400 |
| 役牌 | 200 |
| ドラ1枚 | 50 |
| 2役目以降の複合役1つ | 50 |
| 同一行の過去和了1回 | 100 |
| 2連続目以降の1連続 | ×0.25を加算 |
| 2行目以降の同時和了1行 | ×0.5を加算 |

倍率計算で端数が生じるカスタム設定では、すべての倍率を掛けた最後に小数点以下を切り捨てます。

## 仮定・保留事項

- 初期盤面とブロック牌は136枚をseed付きでシャッフルして決めます。
- ブロックは盤面上端の中央へ出現します。
- 回転時の壁蹴りは行わず、その場で回転後の4マスが収まらなければ回転しません。
- フェーズ2では開始時のドラ表示牌1枚だけを表示し、カンによる追加公開はフェーズ3で接続します。
- 川は全履歴を保持しますが、通常画面の表示枚数と全履歴画面はUIフェーズまで保留します。
- 初期盤面の偶発的な役やカンはフェーズ2では判定・表示しません。
- 混一色は「1種類の数牌と字牌の両方を含む」と解釈しています。
- 現行8役では複数分解によって役集合が異なる具体例を確認できていませんが、分解候補ごとの評価APIは維持しています。
