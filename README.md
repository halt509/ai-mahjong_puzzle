# AI Mahjong Puzzle

作成日・更新日: 2026-07-24<br>
使用AIモデル: GPT-5

Pyxelで制作予定の8×8牌上書きパズルゲームです。現在はフェーズ1のみを実装しており、画面や盤面操作から独立した純粋Pythonのルール判定エンジンを提供します。

## 現在の実装範囲

- 通常麻雀136枚の生成と一意な牌個体ID
- 横1行・8牌の「3枚面子＋3枚面子＋2枚対子」全分解
- 初期採用8役の候補別判定
- 行ごとの取得済み役、再和了、和了回数
- 行ごとの新規カン判定と履歴
- ドラの循環と重複加算
- 設定差し替え可能な仮得点と構造化内訳
- 和了・カン・失敗による連続和了コンボ状態

Pyxel、8×8盤面、テトリミノ、入力、川表示、演出、セーブなど、フェーズ2以降の機能は含みません。

## 必要環境とセットアップ

- Python 3.11以降
- テスト時のみpytest

PowerShellで次を実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[test]"
```

外部ランタイム依存はありません。

## テスト

```powershell
python -m pytest
```

## サンプル実行

セットアップ後に次を実行すると、8牌の和了分解、成立役、新規役、ドラ、得点内訳を確認できます。

```powershell
python -m mahjong_puzzle.sample
```

## 主要モジュール

- `tiles.py`: `TileType`、一意ID付き`Tile`、136枚生成、入力整合性検査
- `hand.py`: `Meld`、`HandDecomposition`、全分解列挙
- `yaku.py`: `Yaku`、分解候補ごとの役判定
- `kan.py`: 4枚一致の候補、新規カン、和了保留フラグ
- `dora.py`: 表示牌からドラへの循環、ドラ枚数
- `scoring.py`: `ScoringConfig`、`ScoreBreakdown`、全候補の採点と最高得点候補の選択
- `state.py`: `LineState`、`TurnState`
- `sample.py`: フェーズ1 APIの一連の使用例

主な公開APIは`mahjong_puzzle.__init__`からインポートできます。役判定の`evaluate_hand()`は基本形の全候補を返します。候補の`is_winning`は役が1つ以上ある場合だけ真です。新規カンがある行は`KanCheckResult.should_defer_win`が真になるため、後続の呼び出し側でそのターンの和了判定を保留できます。

## 仮点数

点数は`ScoringConfig`へ集約してあり、ゲームバランス確定値ではありません。

| 要素 | 仮値 |
|---|---:|
| 全順子 | 100 |
| 全刻子 | 200 |
| 断么九 | 100 |
| 一盃口 | 200 |
| 混一色 | 300 |
| 清一色 | 500 |
| 混老頭 | 400 |
| 役牌 | 200 |
| ドラ1枚 | 50 |
| 2役目以降の複合役1つ | 50 |
| 同一行の過去和了1回 | 100 |
| 2連続目以降の1連続 | ×0.25を加算 |
| 2行目以降の同時和了1行 | ×0.5を加算 |

倍率計算で端数が生じるカスタム設定では、すべての倍率を掛けた最後に小数点以下を切り捨てます。

## 仮定・保留事項

- 混一色は「数牌を少なくとも1枚含み、数牌が1種類で、字牌も少なくとも1枚ある」と解釈しました。字牌だけの手は混一色に含めず、字牌なしの1種類の数牌は清一色だけにしています。
- 複合役ボーナスには取得済み役を含む`current_yaku`の全役数を使い、新規役だけを役基本点へ加算します。
- 同一行ボーナスは今回の和了より前の成功回数に比例します。
- 連続和了倍率には和了ターンを記録した後の連続数を渡します。
- 現行8役では、同じ8牌に複数の有効分解があっても分解依存の役集合が異なる例を確認できませんでした。APIは将来の役追加に備えて候補ごとに判定し、テストでは各候補を個別に検証しています。異なる役集合の具体例が仕様化された場合は回帰テストへ追加します。
- 136枚の初期盤面・ドラ表示牌・配置ブロックへの配分、ドラ表示牌の公開管理、同ターンの複数行処理はフェーズ2または3の保留事項です。
